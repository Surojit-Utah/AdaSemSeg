Proto_FSS (ProtoSemSeg) Reproducibility Summary

Method overview

ProtoSemSeg is a prototype-based few-shot semantic segmentation baseline. It uses a ResNet50 encoder plus a U-Net-like decoder. For each class, foreground and background prototypes are computed from support masks via masked average pooling. Query features are compared to prototypes using cosine similarity, and the resulting similarity maps are passed through a decoder to produce a binary mask per class. The final multi-class mask is assembled by argmax over class-wise predictions.

Prototype computation

  • Support features from encoder layer f32 are masked with class foreground/background split masks.
  • Foreground and background prototypes are computed as masked averages over support examples.
  • Query f32 features are compared to prototypes using cosine similarity, scaled by 20.

Reproduction commands

# 1-shot training
python Main.py --run_id 1 --shots 1 --train --device cuda:0

# 5-shot training
python Main.py --run_id 1 --shots 5 --train --device cuda:0

# Evaluation
python Evaluation_sampling\Main.py --visualize 1 --run_id 1 --shots 5 --eval_mode val --checkpoint_dir <CKPT_DIR> --best_model

Config notes

  • config/local_config.py (train) defaults to F3 inline/crossline only.
  • Evaluation_sampling/config/local_config.py includes Parihaka, F3, and Penobscot; source class is selected interactively.
  • Patch size defaults to 256×256; training uses AdamW, 20 epochs, batch size 2 (train) / 8 (validation).

Gaps / reproducibility issues

  • Hard-coded absolute Linux paths (/home/sci/...) in configs; must be remapped for other machines.
  • Evaluation script is interactive (input() for source class), making batch reproduction difficult.
  • Training uses dataset-specific class weights and assumes prepared .npy volumes + JSON split files.
  • Main.py has a --test argument stubbed out (“Model under progress....”).
  • Checkpoint naming is fixed (bestmodel.pth.tar, Main_0_epXXXX.pth.tar).

Paper alignment

The paper describes ProtoSemSeg as the competing prototype-based FSSS baseline in §5.1.3 and §5.2.3, and notes it is evaluated with the settings from the ProtoSemSeg paper. All methods compared use the same 256×256 patch size.
